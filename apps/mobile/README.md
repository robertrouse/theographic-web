# @theographic/mobile — Capacitor shells

iOS and Android apps that wrap the static web build. Nothing is rewritten:
`cap sync` copies `apps/web/dist` (every prerendered page, the search worker,
the data bundles — 126 MB, ~32 MB compressed) into the app and the WebView
serves it from the bundle. Search, entity pages and the index work with no
network; the place maps still fetch tiles.

## Build and run

```bash
npm ci
THEOGRAPHIC_METADATA_DIR=…/theographic-bible-metadata npm run data   # bundles, once
npm run sync -w @theographic/mobile      # web build + cap sync (both platforms)
npm run ios -w @theographic/mobile       # opens Xcode; Run on a simulator
npm run android -w @theographic/mobile   # opens Android Studio; Run on an emulator
```

Or without an IDE:

```bash
# iOS (needs the iOS platform installed in Xcode — see "What needs Robert")
xcodebuild -project apps/mobile/ios/App/App.xcodeproj -scheme App \
  -sdk iphonesimulator -configuration Debug -derivedDataPath /tmp/theographic-ios \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
xcrun simctl install booted /tmp/theographic-ios/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch booted bible.viz.theographic
xcrun simctl openurl booted "theographic://person/moses_2108"    # deep link

# Android (needs the SDK + JDK 17)
cd apps/mobile/android && ./gradlew assembleDebug
adb install app/build/outputs/apk/debug/app-debug.apk
adb shell am start -a android.intent.action.VIEW -d "theographic://person/moses_2108"
```

iOS dependencies are Swift packages (`ios/App/CapApp-SPM`, generated by
`cap sync`; `Package.resolved` pins `capacitor-swift-pm` 8.5.2). No CocoaPods.

## What is in here

| path                                                          | what                                                                                                                                   |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `capacitor.config.ts`                                         | app id, `webDir`, `androidScheme: https`, splash and system-bar settings                                                               |
| `ios/App/App/ViewController.swift`                            | `StaticSiteRouter`: maps `/person/x` → `person/x/index.html`, else `404.html` — Capacitor's default router serves the root page for every path |
| `android/…/MainActivity.java`                                 | the same routing as a `BridgeWebViewClient` request rewrite (Android's `RouteProcessor` never sees the requested path)                 |
| `ios/App/App/Info.plist`, `App.entitlements`                  | `theographic://` scheme; `applinks:theographic.netlify.app`                                                                            |
| `android/…/AndroidManifest.xml`                               | `theographic://` and `https://theographic.netlify.app` intent filters (`autoVerify`)                                                    |
| `resources/`                                                  | icon and splash sources for `@capacitor/assets` (`npm run assets -w @theographic/mobile` regenerates both platforms)                   |

The web side of the shell is in `apps/web/src/shell/` (loaded only when
`window.Capacitor` reports a native platform): status-bar style follows the
colour scheme, Android hardware back = history back or exit at the root,
incoming URLs are routed by `shellPathFor` (custom scheme, site links, and the
old-URL table). Safe areas are CSS: `tokens.css` reads `env(safe-area-inset-*)`
and the `--safe-area-inset-*` variables Capacitor injects on Android.

The AASA and `assetlinks.json` placeholders are in `apps/web/public/.well-known/`.

## What needs Robert

- **Apple Team ID** → `apps/web/public/.well-known/apple-app-site-association`
  (`TODO_APPLE_TEAM_ID.bible.viz.theographic`) and a signing team in Xcode.
  Enable *Associated Domains* on the App ID in the developer portal.
- **Bundle id / package name.** `bible.viz.theographic` is provisional and is
  the one thing that cannot change after the first upload. It appears in
  `capacitor.config.ts`, `project.pbxproj`, `Info.plist` (URL name),
  `android/app/build.gradle` (`applicationId`, `namespace`), the Java package
  directory, and both `.well-known` files.
- **Android signing certificate SHA-256** → `assetlinks.json`
  (`keytool -list -v -keystore <upload.keystore>`; or the Play Console's
  *App signing* page once Play App Signing is on). Until then App Links fall
  back to the chooser; the custom scheme works regardless.
- **Xcode**: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
  and install the iOS platform (Xcode → Settings → Components, or
  `xcodebuild -downloadPlatform iOS`). Without it Xcode has no simulator
  destination at all (the SDK is there; the runtime is not).
- **Android tooling**: Android Studio (SDK 36, JDK 17). Nothing on the Mac
  today — no `adb`, no `sdkmanager`, no JDK.
- **A vector of the chain mark.** The icon is a 2.9× upscale of the 259-px
  mark in `brand/theographic-logo.png` and is soft at 1024 px.
- **Store listing**: name, subtitle, description, keywords, category
  (Reference), screenshots per device class, privacy policy URL, support URL,
  age rating.

## Gotchas

- `apps/web/dist` must exist before `cap sync` (`npm run sync` builds it).
- Never commit `ios/App/App/public`, `android/app/src/main/assets/public`, the
  generated `capacitor.config.json`, `Pods/`, `build/`, `xcuserdata`, or any
  signing material — `.gitignore` covers all of them.
- Service workers do not run under `capacitor://` on iOS; the shell serves
  from the bundle so it does not need one. CP-09's registration must not
  assume success.
- `@capacitor/assets` is run through `npx`, not installed: it pins an old
  `@capacitor/cli` and a `sharp` with open advisories.
