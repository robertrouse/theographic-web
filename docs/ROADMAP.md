# Roadmap

## Why v2

The 2020 site (Gatsby 2 + Apollo) pulled every page and every search from a
Neo4j GraphQL API at `api.viz.bible`. That backend is gone; the data lives on
as JSON in [theographic-bible-metadata](https://github.com/robertrouse/theographic-bible-metadata).
v2 is a fully static site whose search engine runs in the browser, built so the
same core powers native shells, a CLI, and later an MCP server and an LLM layer.

## v1 scope (checkpoints CP-00..CP-11 — see [CHECKPOINTS.md](CHECKPOINTS.md))

- Data pipeline from the metadata repo at a pinned commit, with a sanity gate.
- Search: references, people, places, events, groups, free text — deterministic,
  explainable, < 30 ms warm, first search < 1 s on a phone. Spec:
  [search-design.md](search-design.md).
- Pages: browse index, chapter reader with entity links, person / place /
  period / event pages, MapLibre maps. Old URLs keep working.
- Generated definitions (Claude, batch, reviewed JSON) replace Easton's as the
  visible description for people, places and events.
- PWA offline; Capacitor iOS/Android shells.

## Explicit non-goals for v1

- Synonym or semantic matching in text search ("love" does not find "charity").
- Any server or database.
- Easton topical entries as pages (the `topics` group is a seam only).
- Search across translations other than KJV.

## Backlog (after v1)

- **Semantic signal**: precomputed quantized verse embeddings + on-device query
  embedding as one more `RankSignal`; no API change.
- **Ask layer**: natural-language questions routed through Claude with `core`
  as the retrieval tool (`QueryRewriter` seam); opt-in key.
- **MCP server** package over `core` (`toolSchemas()`).
- Genealogy and timeline visualisations; Paul's journeys map from
  `geo/pauls_journeys_all.geojson`; LPF geojson integration; Strong's linking.
- Easton topical pages if wanted (`topics` layer, golden #43).
